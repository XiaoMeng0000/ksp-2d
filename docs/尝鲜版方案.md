## 一、背景与问题诊断

### 1.1 现象

GitHub Pages 线上游玩的加载速度与成功率随游戏体量增长持续下降。

### 1.2 根因(实测数据,非估算)

| 首屏阻塞项 | 内容 | 体积 |
|---|---|---|
| 字体预加载 | `fontConfig` 声明 4 个 ttf,其中 2 份含 CJK 的等宽字体各约 18MB | **37.6 MB** |
| 音频预加载 | 全部 11 首 BGM + 12 个音效,**全量 `fetch` + `decodeAudioData`** | **66.5 MB** |
| 天体贴图 | 17 张 PNG(kerbin 4.2MB / pol 7.2MB …) | **84.2 MB** |
| 通用 UI 图标 | 约 40 个 SVG/小 PNG | 1.1 MB |
| **启动遮罩放行前小计** | | **≈189 MB** |
| 主菜单 WebGL 星球 | kerbin albedo 4096×2048 **32MB** + 法线 6.3MB + biome 8MB + detail 1MB | **+47.3 MB** |
| **首屏合计** | | **≈237 MB** |

伴随事实:

1. [main.js](../main.js) 一次性 import 了 **162 个模块 / 2.24MB**,即整个代码库(含部件实验室、WebGL 渲染层、全部着色器)都在首屏加载;gzip 后约 550KB,HTTP/2 下不是瓶颈,但请求数达 **约 260**。
2. [audioCore.js](../src/audio/audioCore.js) 对每个音频条目都 `fetch` + `decodeAudioData`,66MB OGG 解码后 PCM 约 **700MB 内存量级**(估算);低内存设备上极易白屏或崩溃。
3. 仓库跟踪 342 个文件、**511MB**(git pack 347MB);其中 **15 个从未被引用的字重文件占约 260MB**。
4. [latestNewsClient.js](../src/news/latestNewsClient.js) 启动时向 **3 个外部源**并行请求,受限网络下是"成功率下降"的隐藏杀手。
5. 部署工作流 [jekyll-gh-pages.yml](../.github/workflows/jekyll-gh-pages.yml) 只监听 `main`,整站原样上传,无产物裁剪。

### 1.3 结论

**加载慢的主因是资产体积,不是代码体积。** 代码占首屏 1% 不到。因此:

- 体积问题 → 靠"资产四刀"(删天体贴图 / 关菜单星球 / 音频按需 / 字体归零)解决;
- 产品问题(试玩版定位)→ 靠"功能减法"解决;
- 两者分开考核,不得互相替代。

## 二、尝鲜版定位与玩法主线

### 2.1 一句话定位

> **尝鲜版 = 一条完整、可复现的入轨体验线:一键开玩 → 用 ΔV 预算选船/造船 → 机动节点规划 → 时间加速 → 抵达 Mun / Minmus / Duna 系。**

### 2.2 核心玩法确认

**本作的核心玩法是轨道物理**。资源、设施、建造等系统在尝鲜版中只保留"服务轨道物理完整体验"所必需的最小闭环。

### 2.3 多飞船闭环(尝鲜版的真实玩法深度)

```
开局:Kerbin 低轨 · 入门练习船①(ΔV≈1200)+ 轨道船坞(预填材料)
  ↓ 尝试飞 Mun → ΔV 不足 → 回船坞
船坞建造 → ②储备坎巴拉K2号(ΔV≈2800)→ Mun / Minmus 往返 ✅
  ↓ 想飞更远 → 回船坞建造 → ③Duna 往返船(ΔV≈4200)→ duna 系 ✅
追踪站:多飞船列表切换控制
```

这条闭环让"删除飞船编辑器"变得合理:玩家不拼零件,而是**用 ΔV 预算选船**——这正是轨道物理教学的正确形态。

## 三、天体裁剪(17 → 6)

### 3.1 保留范围

| 星系 | 保留天体 |
|---|---|
| `kerbolar` | **Kerbol(恒星)、Kerbin、Mun、Minmus、Duna、Ike** —— 共 6 个 |

### 3.2 删除范围

- 删除 11 个天体条目:Moho、Eve、Gilly、Dres、Jool、Laythe、Vall、Tylo、Bop、Pol、Eeloo(均在 [kerbolarSystem.js](../src/config/world/systems/kerbolarSystem.js) 内);
- 删除 4 个星系文件与其登记:`testSystem.js`、`debdebTestSystem.js`、`debdebSystem.js`、`tuunSystem.js`;
- 删除扫描用丰度表 [bodyResources.js](../src/config/world/bodyResources.js)。

### 3.3 连带动作

1. [starSystemIndex.js](../src/config/world/starSystemIndex.js#L23-L29) 的 `starSystemRegistry` 收缩为单星系;
2. **对外 API 形状不变、内部退化为单星系实现**:`getDefaultSystemIds` / `validateSystemSelection` / `computeSystemPosition` / `getSystemById` 等全部保留,不破坏 `saveManager` 与 `physics.js` 的调用面(接口优先原则);
3. `solarSystemData` 聚合自动收敛为 6 个天体 → 物理默认集、天体图标表、追踪树自动跟随;
4. BGM 分类从 8 类收敛到 5 类(`star` / `terrestrial` / `mun` / `ice` / `duna`),`flight_eve` / `flight_gas` 两首随之无引用;最终文件保留策略见 [7.1](#71-音频)(只留 2 首,其余分类统一映射到 `flight_terrestrial`)。

### 3.4 必须接受的后果

1. 老存档天体集合与 SOI 名不匹配 → **尝鲜版不兼容旧存档**,存档版本号上调,不写迁移;
2. 玩家到不了 Jool 系 / Eve 系 → 这两处是完整版卖点,写入"完整版内容"面板。

### 4.5 明确不做的事

1. **不引入任何第三方框架或构建工具**(项目铁律),包括 Vite / esbuild / webpack;
2. **不做单文件打包**:HTTP/2 下约 115 个请求仅多 100–200ms,却引入打包脚本、sourcemap 与调试成本,违背"简单优先"。若 Pages 实测仍慢再评估;
3. **不做精灵图/图片重编码工程**(图标总量 <50KB,收益趋零),唯一例外见 7.3 的 `ev.png`;
4. **不改物理与轨道数学约定**(r = p/(1+e·cosθ) 等),不触碰数值精度相关逻辑。

## 五、建造链与资源系统设计

### 5.1 底层已具备能力(零架构改动)

| 能力 | 现状位置 |
|---|---|
| 唯一建造入口 | [facilitySystem.buildShip(facilityId, templateId, name, moduleTypeIds)](../src/facility/facilitySystem.js#L373),自带"扣材料 → 创建飞船 → 失败退款"闭环 |
| 新船燃料 | [shipSystem.createShip](../src/ship/shipSystem.js#L29) 按模板 `fuelTanks` **初始满罐** |
| 设施存储 | `cargoSystem` 的 `initFacilityStorage / getStorageAmount / addStorage / consumeStorage` |
| 补给(加油) | `cargoSystem.refuelFromStorage`,经 `facilitySystem` 调用 |

> 结论:砍掉 shipBuilderUI 只是砍掉外壳,建造能力本身留在设施层。

### 5.2 新模块:`src/ui/shipPickerUI.js`

- 定位:替代编辑器的**极简建造选单**,不做模块组装、不做蓝图保存;
- 交互:活动飞船进入船坞交互范围 → 飞行 HUD 出现「建造」按钮 → 点击 -> 弹出模板卡片(②K2 号 / ③Duna 往返船)→ 点「建造」→ 调 `facilitySystem.buildShip(facility.id, templateId, name, [])` → 成功后 `shipSystem.switchShip(newShipId)`;
- 通信:沿用既有事件 `Events.SHIP_BUILDER_REQUESTED`([eventBus.js:57](../src/eventBus.js#L57)),不新增通信词汇;
- 失败反馈:按 `buildShip` 返回的 `reason` 分类提示(材料不足 / 模板异常 / 无设施),文案进 `strings.js`;
- 视觉:遵循 [UI开发规范.md](UI开发规范.md) 与 [UI面板视觉风格规范.md](UI面板视觉风格规范.md)。

### 5.3 补给按钮

- 位置:飞行 HUD,当活动飞船在船坞交互范围内时出现「补给」按钮;
- 行为:调用设施补给接口(内部走 `refuelFromStorage`),按飞船氢/氧缺口补满,受设施存量限制;
- 反馈:成功提示补入量,失败提示"设施无存货"。

### 5.4 资源系统划线(重要修正)

| 模块 | 处理 | 依据 |
|---|---|---|
| `resourceSystem` | **保留** | 质量 / 燃料 / ΔV 记账核心,`computeDeltaV` 在此 |
| `resourceSlot`、`resourceTypes` | **保留** | 槽读写与资源类型表 |
| `modeRules` | **保留**,内部固定 `sandbox` | 建造扣费走"有多少扣多少",否则尝鲜玩家会被材料卡死 |
| `cargoSystem` | **裁剪**:保留 `initFacilityStorage / getStorageAmount / addStorage / consumeStorage / refuelFromStorage`;删除飞船货仓族(`getCargoCapacity / getCargoUsed / getCargoFree / hasCargoHold / getCargoAmount / addCargo / consumeCargo`)、`transferStorageToCargo / transferCargoToStorage / transferBetweenFacilities`、自动物流骨架(`AUTO_LOGISTICS_JOBS / scheduleAutoLogistics / updateAutoLogistics`) | 货仓依赖已砍的 `cargo_hold` 能力 |
| `resourceSystem.getTotalMass` | **删掉货物质量项(2 行)** | 货仓概念已不存在 |
| `resourceHUD` | **保留并精简**:只显示设施存储(材料套装 / 氢 / 氧) | 玩家必须看得见船坞材料存量 |
| `scanSystem` | 删除 | 无扫描玩法 |
| `facilityDeployUI` | **删除,且不留任何入口**(总监决策:彻底消失) | 尝鲜版只保留初始船坞 |

### 5.5 三艘船的数值(冻结)

| 档 | 名称 | dryMass | fuelTanks(H : O = 1 : 8) | isp | maxThrust | 目标 ΔV | TWR |
|---|---|---|---|---|---|---|---|
| ① | 入门练习船(开局) | 2000 | 160 : 1280 | 350 | 60000 | **≈1200** | ≈1.40 |
| ② | 储备坎巴拉K2号(现成,已在库) | 2000 | 280 : 2240 | 350 | 70000 | ≈2800 | ≈1.60 |
| ③ | Duna 往返船(新增) | 6000 | 800 : 6400 | 380 | 220000 | **≈4200** | ≈1.42 |

另有 `momentOfInertia` / `reactionWheelTorque` 需按同量级配套填写,数值终审由总监完成。

**移除**:`debug_behemoth`(测试巨兽)、`rex01_genesis_ark`(测试巨兽promax)——两艘为数值乱填的调试船,留在尝鲜版会直接破坏轨道物理体验。

## 九、双线架构与同步策略

### 9.1 分支语义

| 分支 | 定位 | 产物 |
|---|---|---|
| **`lite`**(从 `main` 切出) | 网页尝鲜版 | GitHub Pages 根路径 |

### 9.2 差异分层

| **资产级**(菜单样式 / 天体贴图 / 音频清单 / 字体清单) | 走 `lite profile` 配置档,**两边共享** |

### 9.3 降低分叉风险的三个约定

2. **`lite` 的减法按目录成组提交**(渲染层 / 实验室层 / 编辑器层 / 内容层),每组"只删不改",不夹带业务改动;
3. **合并方向单向**:玩法/物理改动先落 `main`,再 cherry-pick 到 `lite`;`lite` 的减法改动不回流。

## 十、Electron 桌面版方案

| 项 | 决策 |
|---|---|
| 目录 | 新增 `desktop/`:`main.js`、`package.json`、`builder.yml`(游戏代码仍留仓库根,不复制) |
| **加载方式** | **必须自定义协议**:`protocol.handle('app', …)` 映射到应用内根目录,`win.loadURL('app://-/index.html')`。**禁止用 `file://`**——原生 ES Module 在 `file://` 下会被 CORS 拒绝 |
| 安全 | `contextIsolation: true`、`nodeIntegration: false`、不开放 `node-remote` |
| 体验 | 全屏(`fullscreen: true`)或 `frame: false` + F11、禁用默认菜单、单实例锁、窗口尺寸记忆 |
| 打包 | 先 `--dir` 出便携目录验证;正式用 `electron-builder`:NSIS 安装包 + portable zip 双产物 |
| 体积 | **先删 15 个未引用字重(约 260MB)**,桌面包可从约 600MB 降到约 300MB |
| 自动更新 | `electron-updater` + GitHub Releases(尝鲜期可先关闭) |
| 存档 | `app://` 是独立 origin,与网页端**不互通**;存档落在 Electron userData,版本升级不丢 |
