- **只要该体半径 ≥ 7px（全部真实星球，含最小的 Gilly）→ 图标恒为 7px 且不再变**，

  统一尺寸不会造成"图标比星球本体还大"的物理违和

## 二、问题与目标

### 2.1 现状缺陷

`src/renderer.js` 原有一行硬编码保护：

```js
const BODY_MIN_SCREEN_RADIUS = 3;   // 天体最低屏幕半径
const drawRadius = body.type === 'star' ? physScreenR : Math.max(physScreenR, BODY_MIN_SCREEN_RADIUS);
```

由此产生四个问题：

1. **无身份** —— Jool 与 Gilly 在远处都是同样的 3px 圆点
2. **小卫星被伪放大** —— Gilly 只需缩到 `zoom = 2.3e-4` 就被顶成 3px，凑近看时尺寸失真
3. **中段黑屏** —— `zoom ∈ [1e-8, 1e-6]` 区间内所有行星盘面小于 1px，画面几乎全黑
4. **不可配置** —— 数值硬编码在渲染层，违反「配置进 `src/config/`」原则

### 2.2 目标

- 缩到任意倍率，行星/卫星**始终可辨**（有身份、有量级线索）
- 中等缩放段（`1e-8 ~ 1e-6`）从"黑屏"变为"主天体 + 由远及近的卫星图标"
- 过渡全程**无尺寸跳变、无闪烁**
- 数值全部配置化；恒星行为零改动

## 四、核心机制

### 4.1 共享 LOD 数学（新建 `src/graphics/lod.js`）

现有 Kerbol 过渡区（`renderer.js`）内联实现了一段「easeInOut 缓动 + 几何参数插值」。本方案将其提取为共享函数，图标过渡与恒星 LOD 共用：

```js
// 归一化混合进度 + easeInOut 缓动
export function lodBlendT(value, from, to) {
    const t = (from - value) / (from - to);
    const c = Math.max(0, Math.min(1, t));
    return c < 0.5 ? 2 * c * c : 1 - Math.pow(-2 * c + 2, 2) / 2;
}

// 对数插值（跨尺度参数；from 与 to 同号）
export function lerpLog(from, to, s) {
    if (from <= 0 || to <= 0) return from;
    return from * Math.pow(to / from, s);
}
```

**约束**：恒星改用该函数后，过渡区行为必须**数值等价**（easeInOut 公式与原实现完全一致，`s` 即原 `e`）。

### 4.2 两条判据

| 判据 | 公式 | 作用 |
|---|---|---|
| **A. 分离条件** | `orbitA × zoom ≥ sepPx`（35px） | 与父天体图标不重叠才显示 —— 实现「逐个放行」 |
| **B. 贴图触发** | `displayRadius × zoom ≤ fadeBegin`（8px） | 贴图过小 → 交叉淡入为图标 |

**判据 A 必须用 `orbitA`（轨道半长轴），不能用瞬时距离**：卫星在椭圆轨道上会周期性靠近/远离父体，用瞬时距离会导致图标在卫星绕行一圈中反复闪现。用 `orbitA` 则阈值恒定，**环绕全程稳定**。

无父天体的行星（`orbitParent` 为空）默认 `u = 1`，恒显示。

### 4.3 尺寸与透明度（三段式）

设 `u = min(1, orbitA × zoom / sepPx)`（分离度，见 §4.2）。

**每个天体先确定自己的锁定半径 `R_lockBody`** —— 图标一旦出现，半径锁在它身上不再变，
**且与视图无关**（不得依赖缩放上限，见下方修正记录）：

```
R_lockBody = min(lockRadius, displayRadius)   // 够 7px 的锁 7px；天生不到 7px 的锁自身半径
R_fadeBody = R_lockBody × (fadeBegin / lockRadius)   // 淡入起点，与 R_lockBody 等比例
```

| 段 | 条件 | 贴图 | 图标 |
|---|---|---|---|
| ① 纯贴图 | `R_tex > R_fadeBody` | 半径 `R_tex`，alpha `u` | 不画 |
| ② 过渡带 | `R_lockBody ≤ R_tex ≤ R_fadeBody` | 半径 `R_d`，alpha `(1−t)·u` | 半径 `R_d`，alpha `t·u` |
| ③ 图标档 | `R_tex < R_lockBody` | 不画 | **半径 `R_lockBody`（恒定）**，alpha `u` |

其中：

```
t    = lodBlendT(R_tex, R_fadeBody, R_lockBody)     // 0→1，easeInOut
R_d  = max(lerpLog(R_fadeBody, R_lockBody, t), R_lockBody)
                                                    // 贴图与图标共用的半径：
                                                    // 过渡带内逐帧等大（无跳变），
                                                    // 到 R_lockBody 后不再随 zoom 变化 → 锁死
```

**四个关键性质（即验收要点）**：

1. **图标尺寸锁死** —— 进入图标档后半径恒为 `R_lockBody`，**缩放不再改变图标大小**（这是「缩放保护」的本体）。
2. **无尺寸跳变** —— 过渡带内图标半径逐帧等于贴图半径，交接处两者完全重合。
3. **无闪烁** —— 分离判据用 `orbitA`，恒定不闪。
4. **无消失段** —— 极端缩小下图标由分离度渐隐到 0，不会突然不见。

### 4.4 过渡带与「锁定」的几何关系

图标一旦出现就必须锁死尺寸（验收目标）。要做到**既锁定、又不跳变**，只能靠一件事：
**在过渡带内让图标半径与贴图半径逐帧相等**，到达锁定值时两者正好重合。

因此淡入起点 `R_fadeBody` 必须**大于**锁定值 `R_lockBody`（不能小于）：

- 若起点 < 锁定值：贴图已缩到不足 7px，而图标半径只能从 7px 起算 —— 图标**瞬间出现且比贴图大** → 跳变
- 起点 = 8、锁定 = 7 时：给出 **1px 的回旋空间**，贴图与图标在这段窗口内同步收缩并交叉淡化，
  交接处半径完全重合，此后图标锁定不变

**这是可调参数**：`fadeBegin / lockRadius` 即过渡带倍率 `k`（当前 8/7 ≈ 1.14）。`k` 越大过渡越平缓，
但"贴图开始变淡"也越早；观感上觉得淡入偏早时，优先调小 `k`。

> 注意：这里的 1px 是**全局最小回旋空间**（对已能长到 7px 的天体）。每体的实际窗口为
> `[R_lockBody × k, R_lockBody]`，与 `R_lockBody` 等比，故跨天体口径一致。

### 5.3 染色实现（关键：不可沿用 sasUI 的复用式离屏画布）

`sasUI._tintImage` 使用**单块复用的离屏画布**，每帧覆写 —— 同帧内只能有一种颜色。本场景 17 颗星球同帧、颜色各异，**必须按 (颜色, 尺寸, 合成方式) 各自持有离屏画布并跨帧缓存**：

```
染色流水线（multiply 模式，四步）：
  ① drawImage(模板)                                  画模板
  ② globalCompositeOperation = 'multiply'; fillRect(颜色)   正片叠底上色（保留模板明暗）
  ③ globalCompositeOperation = 'destination-in'; drawImage(模板)  ★ 用模板 alpha 剪回轮廓
  ④ globalCompositeOperation = 'source-over'          还原
```

**③ 是必须的，不是优化** —— 踩过一次的坑：

> `multiply` 在「模板图形之外」的运算结果是 `白色 × 目标色 = 白色`，
> **并且会把 alpha 抬到不透明**，于是整块方形离屏画布被填成白色，
> 贴到画面里图标变成**白方块**（实测：不补 ③ 时 64×64 画布的左上角 alpha = 255、
> 不透明像元 4096 = 整块；补 ③ 后左上角 alpha = 0、不透明像元 3097 = 圆盘+阴影）。

合成方式由 `BODY_ICON_CONFIG.tintMode` 选择：

| 值 | 行为 | 适用素材 |
|---|---|---|
| **`multiply`（默认）** | 保留模板的明暗层次（可承载投影 / 渐变）；白 × 天体色 = 天体色，暗部 → 同色系暗部 | 本体**白色**，可带黑色阴影/渐变 |
| `source-in` | 把所有不透明像素整体换成天体色，**丢弃全部颜色信息** → 模板内的阴影/明暗被抹平 | 纯单色素材（不需求明暗） |

> **为什么不能用 `source-in` 做带阴影的素材**：`source-in` 只看 alpha。
> 「20% 黑阴影叠在白底上」合成后是**灰色但 alpha 仍为 255** 的像素，
> `source-in` 会把它和白色一起替换成同一个天体色 → **阴影彻底消失**（实测只剩 1 种主色）。

### 5.4 渲染接入（`renderer.js` 天体循环）

- 读取 `BODY_ICON_CONFIG` 与 `textureManager.get(cfg.textureKey)`
- **恒星分支不动**（`body.type === 'star'`），仅把过渡插值改为 `lodBlendT` / `lerpLog`，结果数值等价
- 非恒星天体：按 §4.3 三段式计算 `R_d` / 图标半径 / 各自 alpha；`textured` 为 false 时仍保留原有代表色纯色圆兜底
- **星环**：`R_tex ≤ fadeBegin`（进入图标模式／过渡带）时整层不绘制
- **旧常量**：`BODY_MIN_SCREEN_RADIUS` 删除（保护职责由图标机制接管）
- **标签锚点**：`ORBIT_LABEL_DX/DY = 18/−16` 是固定像素偏移，本来就与天体半径无关 —— 已核实无需改动

## 七、验收口径

### 7.1 数值通道

在浏览器控制台按 zoom 序列记录每个 Jool 系天体的 `R_tex / R_d / 图标半径 / 图标 alpha / 是否绘制星环`，与 §4.3 算法逐项比对：

```
10 → 3e-5 → 1.3e-5 → 3.5e-5 → 1.29e-6 → 1e-7 → 1e-8
```

重点核对：
- `R_tex` 穿越 `8 → 7` 时，`R_d` 与图标半径**逐帧相等**
- 分离度 `u` 在卫星环绕一圈中**不变化**（用 `orbitA` 而非瞬时距离）

### 7.2 视觉通道（必须实际截图，不得以"逻辑上应该没问题"代替）

| # | 核对项 |
|---|---|
| 1 | 恒星形态在图标机制生效前后**完全一致**（LOD 选档、光晕层数、过渡区插值） |
| 2 | 缩到 `1e-8` 时画面**只剩 Jool 一个图标**，无卫星、无星环 |
| 3 | 卫星出现顺序**由远及近**（Tylo → Vall → Laythe），放大/缩小双向可逆 |
| 4 | 过渡带内**无尺寸跳变、无闪烁**；连续滚轮来回不产生"呼吸"感 |
| 5 | **Dres 专项**：缩到星环不可见后环带整层消失，且**放大回来能完整恢复**（不是一次性不可逆关闭） |
| 6 | 图标颜色与各体代表色一致（Kerbin `#4488ff`、Duna `#ad3713`、Jool `#3fc144`…），无串色 |
