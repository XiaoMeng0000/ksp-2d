## 四、游戏素材录制（虚拟时钟）

### 4.1 原理

`capture.mjs` 用 `evaluateOnNewDocument` 在游戏加载前注入 `window.__vclock`：接管 `requestAnimationFrame`、`performance.now`、`Date.now`。开启后，游戏的每一帧只在 `__vclock.step(ms)` 时推进，所以**不管机器多卡，录出来都是严格 60fps、零掉帧，而且完全可复现**（同样的脚本录两次结果相同）。

- 游戏主循环 `main.js` 的 `gameLoop(timestamp)` 用 rAF 时间戳算 dt，并钳制在 ≤0.05s。开启虚拟时钟时，时间基准要加 1000ms 余量，避免首帧 dt 为负。
- `stepMs` 设为 50 时，每帧仿真时间是 0.05s × 时间加速倍率，可以用来"快放"长时间点火。
- 每个镜头用全新的隐身浏览器上下文，localStorage 干净。启动流程（关公告 → 开始游戏 → 创建新战役 → 等飞船出现）见 `BOOT.flight`。
- 录制期间把 `window.showNotification` 替换成空函数，避免右上角通知弹窗入镜。

### 4.2 从页面里驱动游戏（同一 ES 模块实例）

页面里 `await import('/src/camera.js')` 与游戏自己导入的是**同一个模块实例**，可以直接改状态。`shots.mjs` 的 `PAGE_LIB` 把常用模块挂在 `window.__M` 上：

| 用途 | 做法 |
|---|---|
| 镜头缩放 | `M.cam.camera.zoom = …`（直接赋值不受缩放上限夹取；飞行场景每帧会把镜头 x/y 跟随活动飞船） |
| 时间加速 | `M.tw.timeWarp.warpToIndex(i)`，档位 `[0,1,2,4,10,50,100,1e3,1e4,1e5,1e6,1e7]`；点火中只能用 `requestPhysicsWarp(2/4)` |
| 机动视图 | `M.view.flightView.enterManeuver(ship, canvas)` / `exitManeuver` / `setFocusByName('Duna', canvas)` |
| 建节点 | `maneuverSystem.createNode(ship, { time })`，只给时刻即可，链解析器 `updateManeuverChain` 会自动补齐快照 |
| 设节点 Δv | 用 `computeNodeAxes(relPos, relVel)` 算出轴，写 `node.dvPro/dvRadial`，再 `rebuildDeltaVFromComponents(node, axes)`，然后 `node._rev++` |
| 读预测 | `getChainNodes()` 里每个节点的 `segments`；段点 `{x,y,t}` 相对 `anchorBody` 在 `anchorTime` 的位置 |
| 选中节点 | `maneuverSystem.setSelectedNode(ship, node)`。**机动视图只画选中节点的链**：想展示转移弧，进机动视图前必须先选中转移节点 |

UT 显示规则：1 天 = 6 小时（21600s），1 年 = 426 天。

### 4.3 Kerbin → Duna 霍曼转移的实现

1. **等窗口**：用时间加速推进到 Duna 领先 Kerbin 约 44.4°（先用 1e7x 粗推到 52° 以内，再用 1e5x 推到 46.5° 以内）。
2. **出发点**：飞船绕 Kerbin 的角度 = Kerbin 公转角 − 55.4°（双曲线渐近线与 Kerbin 公转速度方向对齐）。
3. **搜索**：坐标下降优化节点时刻和顺向 Δv，目标是预测链出现 `Duna` 段，并让 Duna 近拱点半径约 1000 km；最后再细扫 Δv ±4 m/s。实测：节点在约 1838s 后，Δv 1161.4 m/s，飞行 387 天。
4. **执行点火**：逐帧控制，船头锁定到"剩余 Δv 矢量"方向（`heading = atan2(rx, ry)`，与游戏推力 `ax = sin(h)·a, ay = cos(h)·a` 对应），剩余 > 8 m/s 时满油门，之后细油门收尾。
   - **坑**：时间加速 > 1x 时游戏会锁定姿态控制，SAS 转不动船。所以不能依赖 SAS 对准，必须直接写 `ship.heading`。
5. **中途修正**：有限时长点火和计划有偏差，飞船会错过 Duna。修正放在**不入镜**的时刻：建修正节点、搜索（顺向、径向，带 Δv 惩罚项），到点后**瞬时施加 Δv**（`applyImpulse`：改 `ship.vel` 后用 `stateToKepler` 重算轨道）。入镜的点火全部是真实执行的。
6. **捕获**：在 Duna 近拱点建节点，逆向 Δv 从 −50 起每次减 10 m/s 搜索，直到节点后的链全是 `Duna` 段（闭合），再多减 150 m/s。

**已知异常**：捕获段画面里轨道是闭合的，环绕镜头里轨道也闭合，但录制日志里捕获点火刚结束时的轨道读数是逆行双曲线。原因未查清，疑似剩余 Δv 的跟踪在点火中途被重置、导致继续点火烧过了头（`maneuverSystem` 的 trackKey 随节点 `_rev` 变化会把 applied 清零）。画面不受影响；若要重录捕获，建议改成自己积分已施加的 Δv。

## 五、宣传片渲染引擎（`web/`）

- **合成**：所有场景画在离屏 2D 画布 `comp` 上，再上传为纹理，经 WebGL2 后期 pass 输出。后期参数（每帧由场景的 `fx()` 写入）：`rgb` 色差、`glitch` 块错位、`scan` 扫描线、`noise` 颗粒、`flash` 闪白（可换色）、`invert` 反色、`zoom` 径向模糊、`pixel` 像素化、`duo` 蓝黑双色调、`bloom` 泛光、`warp` 桶形畸变、`shake` 震屏。
- **确定性**：`renderFrame(t)` 只依赖 t，随机数全由哈希函数 `rnd(t, …)` 得到，所以任意帧可单独重渲。
- **场景接口**：`{ a, b, prepare?(lt), fx?(lt, t, fx), draw(c, lt, t, fx) }`。`prepare` 负责等素材帧解码（`needClip`）。
- **常用原语**：`text`、`scramble`（乱码解码）、`slam`（冲击缩放曲线）、`diagSplit`（斜切分屏）、`sliceGlitch`、`planet`（圆形裁剪星球贴图）、`marquee`（沿斜线的跑马灯）、`drawClip(c, clip, idx, { src, dst, zoom, cx })`（可裁切局部做 UI 特写）。
- **游戏 UI 风格组件**：`uiPanel`（紫框面板 + 紫头条）、`uiInfo`（深色信息卡）、`uiBar`（绿进度条）、`uiSection`（`// 标题`）、`utString`（UT 时间格式）。颜色取自 `docs/UI面板视觉风格规范.md`。
- **竖版**：URL 带 `?w=1080&h=1920` 时 `VERTICAL = true`，排版按短边 1080 缩放；游戏素材按高度铺满、以 `cx` 为中心裁切。
- **内存**：素材帧 LRU 缓存 `CLIP_CACHE_MAX = 48`。曾设 260，渲染时疑似内存压力导致整机崩溃，**不要调大**。
- **预览**：浏览器直接打开 `http://localhost:3178/web/trailer.html` 可实时播放（空格暂停、←/→ 跳 1 秒）；加 `?render=1` 是录制模式。

**检查流程**（改完分镜必做）：`node tools/render.mjs stills 9.1 13.5 30.2 …` → 运行 `tools/contact.ps1` → 看 `out/contact.jpg`。竖版静帧：先设环境变量 `VW=1080`、`VH=1920`。

## 六、音乐与混音

### 6.1 最终音乐：《Duna 大气层内》

用户提供的文件：`D:\CloudMusic\电台节目\小梦_0000 - Duna大气层内.mp3`（工程内副本 `music/ref/duna_atmo.mp3`，PCM 为 `music/duna_atmo.f32le`）。

- 时长 2:58。强拍每 **3.0s** 一记，下拍相位 0.05s（即原曲 `0.05 + 3k` 秒都是段落/小节起点）；另有 0.6s 的细分节奏。
- 结构（数据分析）：0:00–0:12 安静前奏；0:12 入口（+10 dB）；0:36–0:58 回落；1:00 起有规律重击；1:12 增强；**1:36 高能段开始**（用户最终选定的高潮）；2:12 高频变亮；2:24 全曲最响；2:36 收掉高频的"释放段"；2:48 起淡出。
- 用户选高潮的过程：2:24（能量最大，被否）→ 2:12（试过）→ **1:36（最终认可）**。

**最终音乐映射**（`scenes.js` 的 `MUSIC.map`，片中时间 → 原曲时间）：

| 片中 | 原曲 | 说明 |
|---|---|---|
| 0–9s | 1:27–1:36 | 冷开场，音乐压到 42%（`duck`） |
| 8.38–9s | — | 音乐静音，只留故障声和反向镲，制造"真空" |
| **9s** | **1:36** | **Logo 爆破** |
| 9–30s | 1:36–1:57 | 机动节点 → 离开 Kerbin |
| 30–48s | 2:18–2:36 | 在时间加速开场那一刀往后挪；2:24 最响的一下落在 36s「Duna，到了。」 |
| 48–57s | 2:36 起 | 原曲"释放段"正好落在结尾卡，自然收尾 |

### 6.2 `tools/audio.mjs`

- 输入：帧目录的 `_info.json`（含 `music.map`、`music.fadeIn/fadeOut`、`duck`、`cues`）+ 音乐 PCM（44.1kHz 立体声 f32le，用 ffmpeg 解码）。
- 音乐按 map 拼接，段首尾 15ms 淡化；`duck: [[t, 时长, 增益]]` 做闪避。
- 音效提示表 `CUES` 由 `scenes.js` 里的 `cue(t, type, gain)` 声明。类型：`impact`、`boom`、`thump`、`crash`、`whoosh`、`roar`、`tick`、`glitch`、`glitchHit`、`riser`、`suck`（全部代码合成）；`smp:<名称>` 播放游戏自带音效（`music/sfx/*.f32le`，由 `assets/audio/sfx/*.ogg` 解码而来，例如 `smp:soi_change_1`、`smp:warp`、`smp:maneuver_arrive`）。
- 末端 tanh 软限幅加归一化。成片响度约 −10 LUFS。
- `_info.json` 带 `edit`（竖版剪辑表）时，会自动把音乐映射和音效按片段重排。
- `musicGain: 0` 即无音乐版。只改音乐不改画面时，**不用重渲画面**：改 `_info.json` → 重新混音 → `ffmpeg -c:v copy` 合回原视频。

### 6.3 换一首新曲子的步骤

1. `ffmpeg -i 新曲.mp3 -f f32le -ac 2 -ar 44100 music/xxx.f32le`
2. `node tools/analyze_pcm.mjs music/xxx.f32le`，找节拍周期、强拍间隔和能量跃升点。纯能量判断可能和人耳感受不一致，**高潮位置一定要让用户确认时间点**。
3. 在 `scenes.js` 里改 `BEATLEN`（段长 `BAR = 4 × BEATLEN`，drop 在第 3 段起点）和 `MUSIC.map`。所有分镜时间都由 `BEATLEN/BAR` 推导，素材播放速度会自动跟随。
4. 渲染、混音、编码。

## 七、当前分镜（BAR = 3.0s，DROP = 9s，总长 57s）

| 片中 | 段落 | 画面要点 |

## 八、环境踩坑记录（Windows + DSH 沙箱）

| 现象 | 原因 / 解决 |
|---|---|
| npm 安装失败 `spawn EPERM` | 沙箱禁止 postinstall 子进程，用 `npm i puppeteer-core --ignore-scripts`，npm 缓存设到工程内 |
| PowerShell / curl 下载 HTTPS 失败（schannel） | 沙箱内拿不到 TLS 凭据，改用 Node `fetch`（`tools/dl.mjs`） |
| Chrome 一启动就退出 | 沙箱内无法运行，必须在沙箱外启动，之后通过 9333 端口 TCP 控制 |
| `.ps1` 不能直接运行 | 执行策略限制，用 `powershell -ExecutionPolicy Bypass -File …`，或 `Invoke-Expression (Get-Content -Raw …)` |
| Node 读 JSON 报 `Unexpected token '﻿'` | Windows PowerShell 5 的 `Set-Content -Encoding utf8` 会写入 BOM，JSON 改用 Node 写 |
| 传给 node 的空字符串参数消失 | Windows PowerShell 5 调用原生程序会丢掉 `""` 参数，占位统一用 `-` |
| 整机崩溃 | 疑似素材帧缓存占用内存过大，缓存已降到 48 帧 |
