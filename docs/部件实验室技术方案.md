> **项目代号**：PartLab & ModularShip（3D 部件装配车间与积木式飞船重构）
> **版本**：v3.1（KSP 原版 VAB 布局 + 程序化航天 PBR 材质升级版）
> **技术路线**：原生 WebGL2 3D 渲染（复用 `src/glCore/`）+ 7 类程序化航天 PBR 材质 / 镂空喷管复合几何 / `.obj` 模型 + 实时动态光照
> **定位**：第一阶段在主菜单提供 KSP 原版 VAB 布局的「3D 部件装配车间」完整闭环；第二阶段接入飞行场景（恒星实时追踪光照 + 行星日食阴影）并全面替代旧 `shipTemplates` / `moduleTypes` 模板槽位体系（允许存档断代）

## 0. 版本演进说明（v2.0 → v3.0 重构决策升级）

经与项目总监对齐需求，原 v2.0 仅作为「单轴串糖葫芦、无旋转、不可删改、单图元占位、不进主玩法」的最小脚手架已无法满足重构目标。v3.0 锁定以下核心设计升级：

| # | 维度 | v2.0 局限 | v3.0 正式重构设计（总监已拍板） |
|---|---|---|---|
| 1 | **玩法定位与存档** | 独立玩具，与现有模板永久并存 | **分阶段彻底替代旧模板**（1.B）：先在主菜单测试完整 3D 装配车间，后接入船坞与飞行场景；**允许存档格式断代**，`parts[]` 成为飞船唯一底层数据真源 |
| 2 | **拼装自由度** | 仅上下单轴堆叠、无旋转、不能删除部件 | **轴向节点堆叠 + 径向表面挂载 + $1\times/2\times/4\times$ 环向对称**（2.A）；支持点选部件、整枝删除、撤销/重做（Undo/Redo）及官方预设蓝图 |
| 3 | **几何与模型** | 每个部件仅 1 个纯色光秃圆柱/圆台 | **复合程序化几何体 + 顶点材质分区 + 原生 `.obj` 模型加载**（2.B）：单部件由多子图元（舱体/喷管/法兰环/舷窗/太阳能翼等）合成 1 个 Mesh，支持金属度/高光/自发光分区及外部 `.obj` 网格替换 |
| 4 | **模块与多引擎** | 未整合旧功能模块，仅支持单种引擎 | **旧模块全面实体部件化**（扫描仪/货仓/建设模块/动量轮全部变为可挂载 3D 部件，废除抽象 `moduleSlots`）；支持**多引擎混装**，按推进剂配方独立限流并计算推力加权比冲 |
| 5 | **飞行物理与光照** | 不接入飞行场景 | **聚合刚体飞行（3.A）+ 实时 3D 动态光照（4.A）**：数据结构预留 `stage` 字段；飞行中渲染 3D 飞船，支持 **1.1 恒星方向实时追踪主光** 与 **1.2 行星日食阴影平滑衰减** |
| 6 | **Vendored 镜像保护** | v2.0 计划直接修改 `src/glCore/matrix.js` | **严守 `src/planet/VENDORED.md` 铁律**：绝不修改 `src/glCore/**` 与 `src/geometry/**` 下的任何镜像文件；新增 3D 矩阵/四元数与复合几何全部落位 `src/ship/` |

## 1. 需求与边界

### 1.1 第一阶段目标（Phase 1：主菜单「部件装配车间」完整闭环）

1. **复合 3D 部件库与预设蓝图**：提供 6 大分类、12 种复合几何部件（含指挥舱、燃料罐、真空/大推力化学引擎、氙气离子引擎、分离器、尺寸适配器、动量轮、资源扫描仪、建设集成模块、通用货仓），内置 3 套官方预设蓝图（「坎星K2号」「深空探测者」「轨道工程舰」）。
2. **轴向 + 径向 + 对称拼装**：支持拖拽部件吸附到轴向空闲节点，或贴合到父部件圆柱表面；支持 $1\times / 2\times / 4\times$ 对称模式，实时显示半透明预览体（绿色可装 / 红色拒绝）。
3. **完整编辑体验**：支持点击选中已装部件（联动高亮对称组与子树）、`Delete`/`Backspace` 整枝拆除、`Ctrl+Z` / `Ctrl+Y` 撤销与重做、蓝图 JSON 导入/导出。
4. **物理与能力实时聚合**：从 `parts[]` 实时解算干质量、湿质量、三维质心、绕屏幕法向轴转动惯量 $I_z$（平行轴定理）、动量轮总扭矩、合推力、推力加权比冲、按配方限流后的真实 $\Delta v$、燃烧时长、推重比（TWR）、总造价及飞船特殊能力（资源扫描/设施部署/货仓容量）。

### 1.2 第二阶段目标（Phase 2：接入飞行场景动态光照 & 替换旧模板）

1. **飞行场景实时 3D 渲染与动态光照**：
   - **恒星实时追踪主光（1.1）**：每帧计算当前所属恒星指向飞船的光照向量，飞船转向（`heading`）或公转时，3D 船体明暗交界与高光实时流转。
   - **行星日食阴影遮挡（1.2）**：飞船进入宿主天体背阳面阴影锥时，主光源平滑衰减，仅留深空微光与舷窗自发光。
2. **全面替代旧模板体系**：`shipSystem.createShip` 改由 `parts[]` 蓝图直接生成飞船实例；轨道船坞接入 3D 装配车间；退役 `shipTemplates` 固定模板与抽象槽位，bump `SAVE_FORMAT_VERSION`。

## 4. 拼装与拾取规则

### 4.1 轴向节点吸附（Node Snap）
1. **匹配条件**：
   - 父部件节点空闲（未被其他子部件占用，且不是父部件自身用来连接祖父部件的节点）；
   - 新部件存在方向相反（$\mathbf{d}_{\text{target}} \cdot \mathbf{d}_{\text{new}} = -1$）且尺寸等级相同（`sizeA === sizeB`）的节点；
   - 鼠标距目标节点屏幕投影位置 $\le 42\text{ px}$。
2. **对接变换**：
   - $\mathbf{p}_{\text{new}} = \mathbf{p}_{\text{parent}} + \mathbf{n}_{\text{target}} - \mathbf{n}_{\text{self}}$，`rotationY = 0`，对称档位强制按 $1\times$ 执行。

### 4.2 径向表面挂载（Radial Surface Attach）與 $1\times/2\times/4\times$ 对称
1. **触发条件**：
   - 待装部件 `collider.allowSurfaceAttach === true`；
   - 当前未触发轴向节点吸附，且鼠标射线命中某个 `collider.allowSurfaceChildren === true` 的已装部件圆柱包络。
2. **表面坐标与对称变换**：
   - 设命中父部件中心为 $(x_p, y_p, z_p)$、半径为 $R_p$，待装部件径向贴合偏移为 $r_{\text{self}} = \text{srfAttachOffset}[0]$，挂载高度 $y$ 钳制在 $[y_p - h_p + 0.15, y_p + h_p - 0.15]$；
   - 对称数 $K \in \{1, 2, 4\}$，第 $k$ 个实例（$k = 0 \dots K-1$）方位角 $\theta_k = \theta_0 + \frac{2\pi k}{K}$；
   - 世界坐标：
     $$x_k = x_p + (R_p + r_{\text{self}})\cos\theta_k, \quad y_k = y, \quad z_k = z_p + (R_p + r_{\text{self}})\sin\theta_k$$
   - 绕 Y 轴旋转角 `rotationY` $= -\theta_k$（使部件外法线朝向径向外侧）。

## 5. 物理与能力聚合模型（`src/ship/partPhysics.js`）

1. **质量与三维质心**：
   - $\text{dryMass} = \sum m_{\text{dry}, i}$，$\text{propellantMass} = \sum_{i, r} \text{amount}_{i, r}$，$\text{wetMass} = \text{dryMass} + \text{propellantMass}$；
   - 每个部件的质点位置 $\mathbf{c}_i = \mathbf{p}_i + \mathbf{R}_y(\theta_i)\mathbf{c}_{\text{local}, i}$，总质心 $\mathbf{CoM} = \frac{\sum m_{\text{wet}, i}\mathbf{c}_i}{\text{wetMass}}$。
2. **绕屏幕法向轴（Z 轴）转动惯量 $I_z$**：
   - 单部件自身转动惯量 $I_{\text{own}, i} = \frac{1}{12}m_{\text{wet}, i}(3\bar{r}_i^2 + h_i^2)$；
   - 平行轴定理累加：$I_z = \sum_i \left[ I_{\text{own}, i} + m_{\text{wet}, i}\left((c_{x,i} - \text{CoM}_x)^2 + (c_{y,i} - \text{CoM}_y)^2\right) \right]$。
3. **多引擎推力、加权比冲与配方限流 $\Delta v$**：
   - 按 `engineType` 分组汇总推力 $T_g = \sum_{e \in g} T_e$ 与质量流量 $\dot{m}_g = \sum_{e \in g} \frac{T_e}{\text{Isp}_e \cdot g_0}$；
   - 对每种引擎配方（如 `chemical` 的 $\text{H}_2:\text{O}_2 = 1:8$），根据整船同名推进剂总量求该配方的最大可燃烧推进剂质量 $m_{\text{usable}, g}$ 与可持续燃烧时间 $t_{b, g} = m_{\text{usable}, g} / \dot{m}_g$；
   - 汇总全船合推力 $T_{\text{total}}$、推力加权平均比冲 $\overline{\text{Isp}} = \frac{T_{\text{total}}}{g_0 \sum \dot{m}_g}$、有效可用推进剂总量 $m_{\text{usable}}$，由齐奥尔科夫斯基公式得：
     $$\Delta v = \overline{\text{Isp}} \cdot g_0 \cdot \ln\left(\frac{\text{wetMass}}{\text{wetMass} - m_{\text{usable}}}\right)$$
4. **能力与货仓聚合**：
   - `reactionWheelTorque` $= \sum \tau_i$；
   - `cargoCapacity` $= \sum C_{\text{cargo}, i}$；
   - `capabilities` $=$ 所有部件 `capability` 去重集合，`scanTier` $=$ 最大扫描等级。

## 6. WebGL2 渲染与动态光照模型（`src/ship/shipRenderer3D.js`）

### 6.1 顶点属性布局（交错 11 floats / 44 Bytes）
- `aPosition` (`vec3`): 局部坐标
- `aNormal` (`vec3`): 局部外法线
- `aColor` (`vec3`): 子图元基础漫反射色
- `aMaterial` (`vec2`): `x` = 高光强度 (`specular`), `y` = 自发光强度 (`emissive`)

### 6.2 双模式动态光照（车间模式 + 飞行模式）
片元着色器统一计算：
$$\mathbf{C}_{\text{out}} = \mathbf{C}_{\text{base}} \cdot \left( k_{\text{amb}} + k_{\text{hemi}}(\mathbf{n}\cdot\mathbf{u}_{\text{up}}) + V_{\text{sun}} \cdot k_{\text{diff}}\max(\mathbf{n}\cdot\mathbf{l}, 0) \right) + V_{\text{sun}} \cdot k_{\text{spec}}\max(\mathbf{n}\cdot\mathbf{h}, 0)^s + k_{\text{emissive}}\mathbf{C}_{\text{base}}$$
- **车间模式**：$V_{\text{sun}} = 1.0$，$\mathbf{l}$ 取右前上方固定视角光或世界光，支持开关光照与切换纯色背景。
- **飞行模式（Phase 2）**：
  - **1.1 恒星实时追踪**：$\mathbf{l}_{2D} = \text{normalize}(\mathbf{p}_{\text{star}} - \mathbf{p}_{\text{ship}})$，映射为 3D 光源方向 $\mathbf{l} = (l_x, l_y, 0.28)$；飞船模型矩阵含绕 Z 轴 `heading` 旋转，故旋转飞船或绕恒星公转时明暗与高光实时变化。
  - **1.2 行星日食阴影**：当飞船位于宿主天体背光侧（$(\mathbf{p}_{\text{ship}} - \mathbf{p}_{\text{body}})\cdot \mathbf{l}_{2D} < 0$）且垂直距离 $d_{\perp}$ 落入 $[0.92 R_{\text{body}}, 1.05 R_{\text{body}}]$ 半影带时，$V_{\text{sun}} = \text{smoothstep}(0.92 R_{\text{body}}, 1.05 R_{\text{body}}, d_{\perp})$；进入本影区后 $V_{\text{sun}} = 0$，仅剩微弱环境光与舷窗自发光。

2. KSP2 导出器写的注释 `# map _MetallicGlossMap -> xxx_M (Texture2D)`

> **踩过的坑**：只扫第 1 类会漏掉金属度与 AO 贴图，零件退化成「只有漫反射的塑料」，且不报错。
> 另外 KSP2 导出的大小写不统一（`_M.png` 与 `_m.png` 并存），工具做了大小写不敏感查找。

### E.3 运行时加载与渲染

| 环节 | 实现 |
|---|---|
| 解析 | `src/ship/kspPartLoader.js`：OBJ 按 `usemtl` 切子网格，`v/vt/vn` 去重，多边形扇形剖分 |
| 顶点 | `POSITION(3) + NORMAL(3) + UV(2)`，8 float/顶点 |
| 垂直居中 | 加载时把几何平移到包围盒中心 Y=0，与程序化部件的对称约定统一 |
| 绕序自检 | 计算有向体积，**为负则整体翻转索引**（Unity 左手系 → OpenGL 右手系） |
| 着色 | `src/ship/shaders/kspPartShaders.js`：GGX PBR + 贴图采样 + 无切线法线映射（屏幕导数构造 cotangent frame） |
| 贴图 | 按 URL 懒加载（`textureManager.loadLazy`），不入启动预加载清单 |
| 双管线 | `shipRenderer3D._drawPart()` 统一分流：`type.ksp2` → 贴图管线，否则 → 程序化管线 |

贴图槽位约定（Unity `KSP2/Scenery/Standard`）：

- `_MainTex` → 漫反射（sRGB，shader 内 `pow(2.2)` 线性化）
- `_BumpMap` → 切线空间法线
- `_MetallicGlossMap` → **R = 金属度，A = 光滑度**（roughness = 1 − A）
- `_OcclusionMap` → **G 通道**
- `_EmissionMap` → 自发光
- `_PaintMaskGlossMap` → 涂装遮罩（**暂未使用**，留给玩家自定义涂装）

> **踩过的坑**：`glCore.shader.setUniforms` 对数字型值一律走 `uniform1f`，对 `sampler2D` 会触发
> `GL_INVALID_OPERATION(1282)`。贴图槽位必须绕开它、单独 `gl.uniform1i`。

### E.4 新增配方：甲烷/液氧

KSP2 部件是 methalox（甲烷 + 液氧），与既有 `chemical`（氢 1 : 氧 8）不同，
故在 `engineConfig.js` 新增 `methalox`：`methane:1 / oxygen:4`（CH₄ + 2O₂ 的质量比）。
对应贮箱容量按 1:4 配平（600 / 2400 kg），否则工程师报告会提示「配比余量未利用」。

### E.5 待决策：资产策略

1. **贴图降采样**：1024 → 512/256 可把体积压到约 1/4~1/16；会影响近距离质感，需要实测取舍。
2. **格式打包**：OBJ 文本改自定义二进制（pos/normal/uv 打包）可再省 60~70%，并可省掉解析耗时。
3. **导入范围**：398 个部件全量入仓会拖垮 git 与冷启动；建议只入仓「正式玩法用到的部件」，
   其余由开发者本地导入。
