# 添加新天体标准化流程

本文档描述向 KSP 2D 项目添加新天体的完整流程，涵盖数据验证、配置、贴图声明、自动生效机制与验收清单。

> 0.3.0 更新：贴图改为「就近声明 + 自动注册」——新增普通天体只需改**一个配置文件 + 放一张图**，
> 不再需要登记纹理表或渲染配置表（详见第三章）。

## 一、数据准备（查询与验证）

1. 从 KSP Wiki 获取官方数据，交叉核对 ≥2 个独立来源（wiki.kerbalspaceprogram.com / fandom / ksp-orbit-planner）
2. **必须验证的数据**：

| 数据 | 验证方法 |
|---|---|
| GM | 多源一致 |
| SOI | 多源一致 |
| 轨道半长轴 a | 用开普勒第三定律反算周期核对：`T = 2π√(a³/μ_父天体)` |
| 轨道周期 | 与官方值比对（周期 = 官方时长的强校验） |
| 大气高度 | ⚠ 注意口径差异（Wiki 表格值 vs 模型精确值），与 Kerbin 保持一致口径 |
| 代表色 | 取 ksp-orbit-planner 色值（渲染/轨道线用） |

3. 倾角处理：2D 游戏忽略倾角（方案 A），无需额外字段

## 二、天体配置

1. 在 `src/config/world/systems/<星系>System.js` 的 `bodies` 数组中**插到其父天体之后**
   （数组顺序保证父先子后，`updateCelestialBodies` 速度累加依赖）
2. 标准模板：

```js
new CelestialBody({
    name: 'XXX',            // 名称（追踪树/事件引用用）
    type: 'planet' | 'moon' | 'star',
    musicType: 'terrestrial' | 'rocky' | ...,
    gm: <GM>,
    soiRadius: <SOI>,
    radius: <半径>,
    atmosphereHeight: <大气高度>,  // 无大气为 0
    hasAtmosphere: <bool>,
    color: '#xxxxxx',
    orbitParent: '<父天体名>',
    orbitA: <半长轴>,
    orbitE: <偏心率>,
    orbitOmega: <近点幅角>,
    orbitTheta0: <初始平近点角 rad>,
    textureKey: '<渲染查找键，通常为 name 小写，亦可自定义>',
    texture: 'assets/images/celestial/<星系id>/<name>.png',   // 0.3.0：表面贴图路径（无贴图则省略）
    // 行星专属：
    isHomeworld: false,
    defaultOrbitAltitude: <可选>,
    presetOrbits: { low, mid, high }  // <可选，已由 CelestialBody 透传，驱动 debugUI 预设轨道部署>
})
```

> 注意：`textureKey` 与 `texture` 是**两个不同职责**的字段，不要混用：
> - `textureKey`：`renderableManager` 的注册键（渲染查找用），测试星系的 `testbolar_star` 等自定义键即此类
> - `texture`：贴图资源路径，为空则渲染回退为代表色纯色圆

## 三、贴图声明（0.3.0 起：就近声明，零登记）

1. **放图**：`assets/images/celestial/<星系id>/<name>.png`，规格：1:1 正方形、透明背景、主体圆内切（直径=边长）
2. **写声明**：在上一步的天体配置里加 `texture: 'assets/images/celestial/<星系id>/<name>.png'` —— **仅此一处**

之后无需任何操作：
- 纹理清单由 `src/config/assets/assetManifest.js` 自动聚合，`textureManager` 启动时统一加载
- 渲染层由 `src/graphics/bodyRenderables.js` 按默认规则自动注册（有 `texture` 就画一层表面贴图）

**只有在天体需要「默认规则之外」的渲染时**，才需要改 `src/graphics/bodyRenderables.js` 的例外表：

| 场景 | 做法 | 现有例子 |
|---|---|---|
| 表面贴图 + 程序附加层（如星环） | 在 `bodyRenderableConfigs` 加条目 | `dres`（4 条环带） |
| 按屏幕半径分级 LOD | 加 `modes` + 阈值条目 | `kerbol`（near / far 两档） |
| 无贴图 | 什么都不用做 | 纯色圆兜底，不阻塞开发 |

## 四、自动生效的机制（无需改动）

添加配置后以下系统自动适配（数据驱动）：

| 系统 | 生效内容 |
|---|---|
| 纹理加载 | `assetManifest` 聚合到清单 → `textureManager` 加载 |
| 天体渲染 | `bodyRenderables` 按默认规则注册表面贴图层 |
| SOI 判定 | 非 star 自动成为宿主，飞船可切换 SOI |
| 追踪站树 | `orbitParent` 自动挂到父天体下 |
| 天体轨道线 | 代表色椭圆/圆轨道线 + 右下角 👁 开关 |
| 大气引爆 | 有大气 → 10s 倒计时警告；无大气 → 表面硬边界立即销毁 |
| 危险边界环 | 有大气浅蓝虚线 / 无大气红色虚线，飞船接近时显示 |
| 时间加速限档 | 预测轨道近拱点 < 危险边界 → 锁 4x |
| 部署限制 | 危险边界内禁止部署设施 |
| 轨道预测 | patched conic 自动纳入新 SOI |

## 五、验证清单（验收）

1. **追踪站树**：父天体下出现新节点
2. **渲染**：默认/缩小视距显示天体（贴图或纯色 fallback）+ 代表色轨道线
3. **星系图**：新增天体在「已加载星系」对比图里显示贴图（该场景直接读 `body.texture`）
4. **物理**：SOI 切换正常；轨道参数正确（周期/速度符合官方）
5. **大气行为**（有大气）：进入 → 10s 倒计时警告 → 拉出取消/归零销毁；危险边界环正确显示
6. **时间加速**：撞击轨道限 4x，稳定轨道不限档
7. **部署限制**：危险边界内拒绝部署
8. **回归**：既有天体（Kerbol/Kerbin/Mun/Minmus）渲染与物理不受影响
9. **加载日志**：启动加载画面中该贴图显示 `[OK]`，无 `[FAIL]`
10. **诊断**：GetDiagnostics 0 错误

## 六、注意事项

- **数组顺序**：父天体必须先于子天体出现，否则位置计算错乱
- **字段透传**：天体配置新增任何字段，必须同步在 `src/physics/celestialBody.js` 构造函数中解构并 `this.xxx = xxx`，
  否则配置静默丢失（切换星系时天体经 `structuredClone` 克隆，只保留自有属性）
- **大气高度口径**：全部用 Wiki 表格值（Kerbin 70km、Duna 50km 同口径），避免混用精确模型值
- **贴图缺失不阻塞**：先纯色 fallback 上线，后补贴图（此时仅需加 `texture` 一行）
- **周期验证**：添加后核对 HUD 显示的轨道周期与官方值误差 <1%
- **存档兼容**：新天体对旧存档无损（存档只存飞船/设施相对坐标，不存天体表）

## 七、附：与天体相关的其它资产就近声明位置（0.3.0）

| 资产 | 声明位置 | 字段 |
|---|---|---|
| 天体表面贴图 | `src/config/world/systems/*.js` | `texture` |
| 飞船模块图标 | `src/config/entities/moduleTypes.js` | `iconTexture` |
| 飞船能力工具栏图标 | `src/config/entities/moduleTypes.js` 的 `CAPABILITY_TOOLBAR` | `iconTexture` |
| 设施 / 舱室图标 | `src/config/entities/facilityTypes.js` | `iconTexture` |
| 飞船船体两态图 | `src/config/entities/shipTemplates.js` | `textures: { active, inactive }` |
| 无主通用 UI 图标 | `src/config/assets/textureConfig.js` | 短 key（集中表） |
