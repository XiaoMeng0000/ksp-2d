# KSP 2D 图片注册/加载标准化流程 v2.1

> 0.3.0 更新（资产就近声明）：图片声明从「单一集中表」改为「**分层声明**」——
> 有实体归属的资产写在实体自己的配置里，只有无主的通用 UI 图标才留在集中表。
> 新增实体资产不再需要改 `textureConfig.js`。
> v2.1 补充：总则新增**三条判据**，用于回答「这块东西该放哪」——声明层与字节层是两条不同的轴。

## 一、总则（铁律）

1. **分层声明**：
   - **有实体归属**的资产 → 就近声明在实体配置中，路径即清单 key
   - **无实体归属**的通用 UI 图标 → 集中在 `src/config/assets/textureConfig.js`（短 key）
2. **清单自动聚合**：`src/config/assets/assetManifest.js` 收集两类声明合成加载清单，
   由 `textureManager` 统一加载。**禁止手工维护第二份资源清单**
3. **禁止硬编码**：业务代码禁止 `new Image()`、禁止写死图片路径；
   需要 URL 字符串时（如 CSS `mask-image`）走 `getTexturePath(key)`
4. **永远带 fallback**：纹理未就绪/加载失败时必须回退到 Emoji 或程序化绘制
5. **分类存放**：素材必须放对应分类文件夹，不堆在 `images/` 根目录

### 三条判据（回答「这块东西该放哪」）

**判据一 · 声明归谁管 —— 看「一对一还是一对多」**

| 形态 | 归处 | 例 |
|------|------|-----|
| **一对一**：某实体专属 | 就近写在该实体配置里 | 天体 `texture`、模块 `iconTexture` |
| **一对多**：跨实体共享的兜底/默认 | 集中表 `textureConfig.js` | `ship_default_active`、`facility`（看似属于飞船/设施，实为所有实体共用的兜底图） |
| **无主**：纯 UI 装饰 | 集中表 `textureConfig.js` | SAS 图标、时间加速图标 |

> 分界是**一对一还是一对多**，不是「名字里有没有实体」。

**判据二 · 素材文件放哪 —— 看「资源与实体的关系形态」**

| 关系形态 | 组织轴 | 例 |
|----------|--------|-----|
| **一一对应** | 按**内容归属**分层 | `celestial/<星系id>/<天体>.png` |
| **一对多**（按类别选） | 按**语义类别** | `audio/bgm/flight_mun.ogg`（「Mun 类天体的音乐」，不是 Mun 专属） |
| 按界面归属 | 按**界面区域** | `ui/` `sas/` `menu/` |
| 按功能部件 | 按**部件** | `facilities/compartments/` |

**判据三 · 硬约束：代码树与二进制分离**

素材一律放 `assets/`，**禁止放入 `src/`**。大体积二进制混进源码树会让 git 仓库、编辑器索引与代码搜索全部失效 —— 这是约束，不是偏好。

> 一句话记法：**声明层问「谁拥有它」，字节层问「它和实体的关系是什么形状」。**
> 两者是两条不同的轴，不要用一条轴去套所有资产。

## 二、素材放置规范

```
assets/images/
├── menu/            主菜单（背景、Logo、反馈图标）
├── ui/              通用 UI（时间加速、垃圾桶、ESC 菜单图标等）
├── sas/             SAS 模式图标 + 导航球方向图标
├── facilities/      设施
│   └── compartments/ 设施舱室
├── celestial/       天体贴图（按星系分目录，与 config/world/systems/ 一一镜像）
│   └── <星系id>/     如 kerbolar/  → kerbin.png / mun.png / …
└── ships/           飞船
    └── hulls/       船体图标（飞行场景）
```

## 三、命名规范

| 前缀 | 用途 | 示例 |
|------|------|------|
| `comp_` | 设施舱室（**仅通用表内**，实体配置里直接用路径） | `comp_bridge` |
| `icon_` | 通用动作图标 | `icon_deploy_facility` |
| `mod_` | 飞船模块（**仅通用表内**） | `mod_test_ballast` |
| `ship_` | 船体兜底图 | `ship_default_active` |
| `ui_` | UI 控件 | `ui_trash_can` |
| `dir_` | 导航球/圆盘方向图标 | `dir_prograde` |
| `{body}.png` | 天体贴图（文件名 = 天体名小写，放 `celestial/<星系id>/` 下） | `celestial/kerbolar/kerbin.png` |

## 五、五大场景标准流程

### 场景 1：DOM 图标（面板/列表/工具栏）

**链路**：`实体配置.iconTexture 或 textureConfig 短 key → assetManifest → textureManager → renderIconHtml() → <img>`

```
① 放图片  → assets/images/对应分类/
② 声明    → 实体配置写 iconTexture（有归属）或 textureConfig 加一行（无归属）
③ 使用    → ${renderIconHtml(路径或短key, '❓', 尺寸)}
```

**已有实现**：`uiComponents.js`、`flightUI.js`、`sasUI.js`、`timeWarpUI.js`、`facilityDeployUI.js`、`shipBuilderUI.js`、`trackingUI.js`

**SVG 图标规范**：
- SVG 必须带 `width` + `height` + `viewBox` 三件套（`textureManager` 用 `new Image()` 加载，缺尺寸会导致浏览器布局异常）
- **白色单色模板底稿**：图标形状用白色描线绘制，状态色由渲染层运行时染色
  （Canvas 用离屏 `source-in` 模板染色，见 `sasUI.js _tintImage`；DOM 用 CSS `mask-image` + `background`）

### 场景 2：Canvas 全屏背景

**链路**：`textureConfig → textureManager → drawImage`

```
① 放图片  → assets/images/menu/
② 声明    → textureConfig.js 加 menu_bg
③ 使用    → 优先 drawImage(bg, 0,0,W,H)；失败 fillRect(black) + 原有星空绘制
```

**参考**：`menuScene.js`

### 场景 3：Canvas 场景静态图（Logo/海报）

**链路**：`textureConfig → textureManager → drawImage / img.src`

**参考**：`menuScene.js`、`splashScene.js`、`creditsScene.js`、`licenseScene.js`

### 场景 4：Canvas 天体贴图

**链路**：`天体配置.texture → assetManifest → textureManager → renderableManager → drawImage`

```
① 放图片  → assets/images/celestial/<星系id>/<name>.png
② 声明    → 天体配置加 texture: 'assets/images/celestial/<星系id>/<name>.png'
③ 渲染    → bodyRenderables 默认规则自动注册（有 texture 即画一层）；无需任何登记
```

**参考**：`renderer.js`、`galaxiesScene.js`、`flightUI.js`（扫描目标卡）

> 渲染层查找键是 `body.textureKey`（≠ `texture` 路径），两者职责不同，见《天体添加流程》第二章注。

### 场景 5：Canvas 轨道图标（飞船/设施）

**链路**：`实体配置 → assetManifest → textureManager → drawImage（带解析优先级）`

**飞船解析优先级**（`renderer.js`）：

```
① 模板 textures[active/inactive]（按 templateId 实时解析，老存档同样生效）
② 未配置 → 通用兜底 ship_default_active / ship_default_inactive
③ 纹理未加载 → 程序化三角形
```

**设施解析**：`facilityTypes.FACILITY_TYPES[].iconTexture`；未配置 → 通用兜底 `facility`

**缩放保护**：受控/选中 `max(14, 16*zoom)`，非受控/未选中 `max(4, 8*zoom)`

### 场景 6：renderableManager 实体（可选多层渲染）

**链路**：`声明 → assetManifest → textureManager → renderableManager → renderer.js layer.texture`

```
main.js TEXTURES_READY 回调中：
renderableManager.register('facility', { layers: [{ texture: 'facility', ... }] })
```

**参考**：`main.js`、`renderer.js`、`bodyRenderables.js`

## 六、新增资产的判断流程

```
新图片到手
  ├─ ① 它和实体的对应关系是什么形状？（判据一）
  │    ├─ 一对一（某天体/模块/设施/飞船模板专属）
  │    │     └─ 写进该实体的配置字段（texture / iconTexture / textures）
  │    ├─ 一对多（跨实体共享的兜底或默认图）
  │    │     └─ 加进 src/config/assets/textureConfig.js
  │    └─ 无主（纯 UI 装饰：菜单/ESC/SAS/时间加速…）
  │          └─ 加进 src/config/assets/textureConfig.js
  ├─ ② 文件放哪？（判据二）按资源与实体的关系形态选轴
  │    ├─ 一一对应 → assets/images/<类别>/<归属分层>/<名>.png（如 celestial/kerbolar/）
  │    ├─ 按语义类别 → assets/audio/bgm/ 这类按类别分
  │    └─ 按界面区域 / 按部件 → ui/ sas/ menu/ facilities/compartments/
  └─ ③ 无论哪种，都无需改 assetManifest.js 与 textureManager.js
     （素材位置见判据三：一律在 assets/，禁止放 src/）
```

## 七、故障排查

| 现象 | 排查点 |
|---|---|
| 启动加载画面出现 `[FAIL] 文件名` | 该路径文件不存在或路径写错；`[FAIL]` 行显示的是**文件名**，完整路径见浏览器控制台 `[TextureManager] 加载失败` |
| 图标显示为 Emoji 而非图片 | 1) 声明路径错 2) 文件缺失 3) 消费方传的字段名不对 |
| 图片已加但没加载 | 检查是否真的被 `assetManifest` 聚合到——有归属的资产必须挂在实体数组里（如未加入 `SHIP_TEMPLATES` 的模板不会被聚合） |
| CSS 里要图片 URL | 用 `getTexturePath(key)`，不要写死路径 |
