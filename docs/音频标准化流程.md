# KSP 2D 音频注册/加载/播放标准化流程 v1.0

## 一、总则（铁律）

1. **唯一注册中心**：所有音频必须在 `src/audio/audioConfig.js` 声明 key→path，由 `audioCore` 统一加载解码
2. **禁止硬编码**：业务代码禁止 `new Audio()`、禁止直接操作 AudioContext、禁止写死音频路径
3. **事件驱动决策**：播放/停止决策全部由 `audioDirector` 订阅事件总线完成；业务层只 emit 游戏事件，不直接调用播放
4. **数据驱动映射**：场景→音乐、天体分类→音乐 的映射只写在配置里，不写死在逻辑中
5. **分类存放**：音乐放 `assets/audio/bgm/`，音效放 `assets/audio/sfx/`，不堆根目录
6. **永远带容错**：音频未就绪 / 资源缺失时静默跳过，绝不阻塞游戏流程、不抛异常

## 二、素材放置规范

```
assets/audio/
├── bgm/   背景音乐（菜单、飞行、追踪站）
└── sfx/   UI 与游戏音效（预留空目录，待音效任务填充）
```

## 三、命名规范

**文件名**：`{场景}_{分类}.ogg`

| 文件 | 含义 |
|------|------|
| `menu1.ogg` / `menu2.ogg` | 菜单音乐变体 KSP1 / KSP2 |
| `flight_terrestrial.ogg` | 类地天体（Kerbin）飞行音乐 |
| `flight_mun.ogg` | Mun 分类飞行音乐 |
| `flight_star.ogg` | 恒星（Kerbol）飞行音乐 |
| `tracking.ogg` | 追踪站音乐 |

**资源标识**（manifest 键）：`music:<sceneKey>[_<variantKey|bodyType>]` 或 `sfx:<key>`

| 标识 | 示例 |
|------|------|
| `music:menu_ksp1` | 菜单 KSP1 变体 |
| `music:flight_mun` | Mun 分类飞行音乐 |
| `music:tracking` | 追踪站（无子项结构） |

**天体音乐分类**（`CelestialBody.musicType`）：`terrestrial` / `mun` / `star` / `icy` / `rocky` / `gas` / `eve` / `duna` / `deepSpace`

## 四、驱动链路总览

```
audioConfig（注册）──▶ audioCore（加载/解码/播放/音量总线）──▶ 出声
                           ▲ 事件
audioDirector（订阅事件总线，查表决策）
   └─ SCENE_CHANGED / SOI_CHANGED ─▶ gameState ─▶ getMusicTypeForSOI ─▶ audioCore.playMusic
```

三层职责：`audioConfig` 数据层（声明）、`audioCore` 引擎层（播放能力）、`audioDirector` 决策层（事件→动作）。业务层与音频完全解耦。

## 五、三大场景标准流程

### 场景 1：固定场景音乐（菜单 / 追踪站）

**链路**：`audioConfig → audioDirector(SCENE_CHANGED) → audioCore.playMusic(sceneKey[, variant])`

```
① 放音乐  → assets/audio/bgm/
② 注册    → audioConfig.js musicMap 加条目
             （variants 结构支持同一场景多曲切换）
③ 接线    → audioDirector._handleSceneChanged 加 to===sceneKey 分支
④ 生效    → 进入场景自动播放，离开自动停止
```

**参考**：`audioDirector.js:38`、`settingsScene.js`（菜单音乐 KSP1/KSP2 按钮组）

### 场景 2：飞行场景按宿主天体分类选曲

**链路**：`audioConfig.byBodyType → audioDirector(SCENE_CHANGED / SOI_CHANGED) → getMusicTypeForSOI → audioCore.playMusic('flight', musicType)`

```
① 放音乐  → assets/audio/bgm/flight_<分类>.ogg
② 注册    → audioConfig.js musicMap.flight.byBodyType 加一行  <分类>: 'path'
③ 标天体  → solarSystem.js 给 CelestialBody 加 musicType: '<分类>'（与 byBodyType key 一致）
④ 生效    → 进入飞行按焦点天体播，SOI 跨越自动切曲
```

**规则**：
- 焦点优先级：活动飞船 > 活动设施（设施模式下 `activeShipId` 为 null，回退查活动设施的宿主天体）
- 深空（无 SOI）→ `deepSpace`；天体未分类 → 兜底 `rocky`

**参考**：`physics.js getMusicTypeForSOI`、`audioDirector.js:57`

### 场景 3：音效（预留，未实现）

**链路**：`audioConfig.sfxMap → audioCore（_sfxGain 总线已建，播放接口待实现）`

当前状态：`sfxMap` 空、播放接口未实现。**所有 UI 点击统一使用一个音效**（总监既定规则），待"UI 统一音效"任务填充。

**规则**：UI 层 emit 事件，audioDirector 查 `sfxMap` 播放，业务层不直接出声。

## 六、audioDirector 事件订阅表

| 事件 | 条件 | 动作 |
|------|------|------|
| `SCENE_CHANGED` | `to === 'menu'` | `playMusic('menu', getMenuMusicVariant())` |
| `SCENE_CHANGED` | `to === 'flight'` | 按焦点物体天体分类播放 |
| `SCENE_CHANGED` | `to === 'tracking'` | `playMusic('tracking')` |
| `SCENE_CHANGED` | `from ∈ {menu, flight, tracking}` 且到无音乐场景 | `stopMusic()` |
| `SOI_CHANGED` | 当前场景为 `flight` | 重新按焦点物体天体分类播放 |

## 七、加载与自动播放解锁

- **加载**：`main.js` 将 `audioCore.init()` 与纹理加载并行启动，fetch + `decodeAudioData` 解码为 AudioBuffer
- **进度事件**：`AUDIO_PROGRESS`（单资源）/ `AUDIO_READY`（全部完成）/ `AUDIO_LOAD_ERROR`（失败）；加载界面音频进度条随事件更新，**纹理与音频都就绪才进入 splash**
- **失败不阻塞**：单个资源失败仅记录并提示，游戏照常进入
- **自动播放策略**：AudioContext 初始为 suspended，首次用户点击/按键后由 `audioCore` 统一 `resume()`
- **调试入口**：`window.__audioCore` / `window.__audioDirector`
