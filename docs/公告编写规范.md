# 公告编写规范

> 适用版本:公告栏面板化(0.2.4)后
> 本文档定义公告内容(文案与结构)的编写规则,所有公告一律按本规范编写
> 数据结构见 `src/config/announcementConfig.js`;渲染面板见 `src/scenes/infoScene.js`;视觉规范见 `UI面板视觉风格规范.md`

---

## 一、公告的视觉结构(编写前必读)

公告栏是「左侧版本导航 + 右侧卡片流」的 KSP2 面板,文案层级只有**两级**:

```
版本大标题  ── 右侧内容区顶部 // 标题(accent 蓝)
卡片小标题  ── 每张卡片的紫头条(--theme-btn-selected)
卡片正文    ── 紫头条下的深色卡体段落
```

**编写公告 = 把内容切成一叠卡片,每张卡片 = 一个小标题 + 若干段落。**

---

## 二、标题分级规则(核心)

### 2.1 禁止大纲编号

卡片头**一律不用**「一、」「二、」「1.」「(1)」等大纲编号。

- 卡片化后所有卡片头同屏并列,编号层级(一/二/三)没有载体,只会造成「大标题」与「小标题」混乱;
- 编号原本表达的从属关系,由「卡片先后顺序」自然承接:上一张卡片讲完,下一张卡片自然接续。

错误示例:`一、0.2.3 公测版回顾` / `三、0.2.3 → 0.2.4 一览`
正确示例:`0.2.3 公测版回顾` / `0.2.3 → 0.2.4 一览`

### 2.2 大节不单独成卡

原文若有大节(如「二、0.2.4 beta 带来了什么」)及其下小节(如「资源系统:燃料不再是一个数字」),**只保留小节作为卡片**,大节标题不单独成卡、也不作为任何前缀。

- 大节标题往往只是一句过渡话,本身没有内容,单独成卡等于一张空卡;
- 大节语义由版本大标题 + 卡片顺序承担。

### 2.3 卡片小标题的命名格式

| 场景 | 格式 | 示例 |
|------|------|------|
| 主题块 | `主题:副题`(冒号后为一句概括) | `资源系统:燃料不再是一个数字` |
| 回顾/对比 | 纯名词短语 | `0.2.3 公测版回顾` / `0.2.3 → 0.2.4 一览` |
| 提示类 | 纯名词,不带括号说明 | `测试重点`(非「测试重点(请各位玩家重点体验)」) |
| 首尾 | `引言` / `结语` | `引言` / `结语` |

规则:
- 标题末尾不加句号;不用括号补注释(括号内容并入正文首段);
- 标题内不出现版本号以外的大纲痕迹(如「第 X 部分」);
- 冒号统一用中文全角 `:`。

### 2.4 版本大标题

- `title` 字段:全角说明性标题,如 `轨道工程师 0.2.4`(显示为 `// 轨道工程师 0.2.4`);
- 可省略(渲染时回退显示 `version`);
- 不要带 `[ksp2d:oe ...]` 这类文件命名风格的前缀。

## 三、正文段落写法

- `paragraphs` 为字符串数组,**每一项渲染为一个 `<p>` 段落**(卡体内行高 1.9);
- 一段一个信息点:一个句子、或一个列表项(列表项直接作为段落,不要在段内用 `\n` 或 `\n\n` 模拟换行);
- 正文是**纯文本**,不解析 Markdown —— 不要写 `**加粗**`、`- 列表`、`# 标题` 等语法;
- 中文引号用全角 `“ ”`;数字、符号(→、ΔV、engineOut)照常用半角。

示例(资源系统卡):

```
title: 资源系统:燃料不再是一个数字
paragraphs: [
    '氢/氧分槽:燃料按引擎配方分槽存储(液氢:液氧 = 1:8),燃烧时按配方独立消耗,每槽各有进度条',
    '引擎停机机制:任一燃料耗尽,引擎进入 engineOut 停机状态——而不是永久报废!补给后即可恢复点火。',
    '质量更真实:总质量 = 干质量 + 全部推进剂存量,载荷越重 ΔV 越低'
]
```

## 四、排序规则(无需手动维护)

- 手写数组顺序**随意**,导出前自动排序;
- **当前版本公告置顶**(与 `version.js` 的 `VERSION_TEXT` 比较版本段,忽略 `-alpha` 等后缀与 Build 号);
- 其余按版本号**从早到晚**;
- 无当前版本公告时,最早的版本在最上;
- **常驻条目固定排最后**:`version` 不带版本号(如 `反馈渠道`)的条目不参与时间线,始终位于列表末尾 —— 用于与版本无关的常驻信息;
- `version` 字段建议与游戏版本号一致(如 `v0.2.4`),否则该版本不会被识别为「当前」。

---

## 五、新增 / 修改公告流程

1. 打开 `src/config/announcementConfig.js`,按上表结构在 `ANNOUNCEMENTS` 数组追加或修改条目;
2. 无需调整条目顺序(自动排序);
3. 若数组为空,启动流程自动跳过公告页直接进主菜单;
4. 浏览器验证:
   - 启动 → 公告页 → 左侧导航高亮当前版本;
   - 逐卡检查:紫头条无编号、正文段落换行正确;
   - 切换其他版本导航,确认内容跟随。

        }
    ]
}
