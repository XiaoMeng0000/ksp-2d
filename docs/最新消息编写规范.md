# 最新消息编写规范

> 适用版本：0.3.0（启动弹窗「最新消息」上线后）
> 本文档定义**在线最新消息**的内容规则；内容本身存放在**独立于游戏仓库**的 GitHub 仓库中
> 数据结构与数据源见 `src/config/ui/latestNewsConfig.js`；拉取逻辑见 `src/news/latestNewsClient.js`；
> 渲染面板见 `src/ui/latestNewsUI.js`；视觉规范见 `UI面板视觉风格规范.md`
> 游戏内「游戏公告」（版本更新日志）的编写规则另见 `公告编写规范.md`，两者不是一回事

---

## 一、「最新消息」与「游戏公告」的分工

| | 最新消息（本文档） | 游戏公告（`公告编写规范.md`） |
|---|---|---|
| 定位 | 制作组最近在做什么 + 游戏最新消息的**摘要** | 每个版本的完整更新说明（历史留档） |
| 长度 | ≤200 字，一段话 | 多卡片、可长文 |
| 位置 | 启动进主菜单时自动弹出 | 主菜单一级入口「游戏公告」 |
| 内容源 | **独立在线仓库**，改完即生效，不用发版 | 游戏仓库内 `src/config/ui/announcementConfig.js`，随版本发布 |
| 更新频率 | 随时 | 每次发版 |

铁律：**最新消息只写摘要，详情一律引导去「游戏公告」**。弹窗底部「去公告查看」按钮就是为此准备的。

---

## 二、内容仓库结构

最新消息的内容放在独立仓库（默认坐标见 `latestNewsConfig.js` 的 `sources`）：

```
<内容仓库>/
├── news.json            ← 唯一数据文件，游戏只读这一个
└── README.md
```

**0.3.0 起不再使用仓库里的图片**：配图改为游戏内置图库（见第五节），仓库只需要 `news.json`。
历史遗留的 `images/` 目录可以删掉。

客户端**三源竞速**（谁先返回合法内容用谁，其余立即取消，总窗口 3 秒）：

```
pages    : https://xiaomeng0000.github.io/ksp2d-news/news.json
jsdelivr : https://cdn.jsdelivr.net/gh/XiaoMeng0000/ksp2d-news@main/news.json
raw      : https://raw.githubusercontent.com/XiaoMeng0000/ksp2d-news/main/news.json
```

⚠️ **jsDelivr 会延迟 800ms 才出场**：它对 `@main` 分支有 12 小时级缓存，推送后可能返回**旧版 JSON**
（典型症状：面板有文字但没配图，因为旧版没有 `type` 字段）。因此只让它在 Pages / raw
都没返回时兜底，正常情况永远是 Pages 的内容。

**推送后以 Pages 为准**：Pages 构建约 1 分钟、CDN 刷新约 10 分钟，之后玩家重启游戏即可看到新内容。

## 三、news.json 格式

```json
{
    "schemaVersion": 1,
    "id": "2026-06-01-a",
    "updated": "2026-06-01T10:00:00Z",
    "title": "最新消息",
    "type": "progress",
    "text": "制作组最近在收尾下一代渲染层……\n完整改动都在游戏内「游戏公告」里。",
    "enabled": true
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `schemaVersion` | 是 | 固定 `1`。客户端只认 `1`，其他值视为无效内容（保护旧客户端） |
| `id` | 是 | 唯一标识，格式 `YYYY-MM-DD-序号`。改内容就换 `id`。**同一 `id` 代表同一条消息** |
| `updated` | 是 | ISO 8601 UTC 时间，改内容时同步更新（用于排查「线上是哪一版」） |
| `title` | 否 | 面板标题，省略时显示「最新消息」 |
| `type` | 否 | **通知类型**：`release`（新版本发布）/ `progress`（制作组刚做好或正在做）/ `issue`（开发遇到问题），大小写不敏感。游戏按类型选内置配图；缺失或未知 → 面板不显示图片 |
| `text` | 是 | 正文纯文本，≤200 字，换行用 `\n`。**禁止 HTML / Markdown**（客户端按纯文本渲染） |
| `enabled` | 是 | `false` 表示临时下线：客户端清掉本地缓存并当作「没有消息」处理 |

文件要求：

- **UTF-8 无 BOM**（带 BOM 会导致解析失败，客户端静默降级）；
- 4 空格缩进，中文不转义成 `\uXXXX`（方便直接手改）；
- 顶层只允许上表字段，不要自行增加字段（未来扩展走 `schemaVersion` 升级）；
- **旧字段 `image`（远端图片 URL）已废弃**，0.3.0 客户端完全忽略它。

## 四、正文写法

1. 总长 ≤200 字（客户端对超长内容按 400 字硬截断，但规范要求 200 以内）；
2. 建议句式：**第一句说现在在做什么，第二句说玩家之后会得到什么**；
3. 不用 HTML、不用 Markdown、不加「一、二、三」这类大纲编号；
4. 分段用 `\n`，最多两段（面板正文区超过 168px 会内部滚动）；
5. 不写具体日期承诺（「下周上线」这类），写进度与方向；
6. 结尾可自然引导一句「详见游戏内公告」，但**不必**写「点击下方按钮」（按钮自己会说话）。

示例：

> 制作组正在收尾下一代渲染层，主菜单背景换成实时渲染的 3D 星球，地表会随光照起伏。
> 本月还会修掉几处飞行手感问题。完整改动都在游戏内「游戏公告」里。

## 五、配图：由通知类型 type 决定，图片只能用内置的三张

图片**随游戏本体发布**（`assets/images/news/`），内容仓库不再上传图片，`news.json` 只写**通知类型 `type`**，
游戏内部查表（`latestNewsConfig.typeImages`）决定用哪张图：

| `type` | 画面 | 用在什么时候 |
|---|---|---|
| `release` | 角色撒礼花 + 游戏 LOGO | 新版本发布 |
| `progress` | 角色拿放大镜 | 制作组刚做好一个东西、或正在做什么 |
| `issue` | 角色头顶问号 | 开发遇到问题、预期变更、风险告知 |

规则：

- 图片由客户端本地加载（不进网络），**断网也有图**；
- 客户端按原图比例自适应显示（不裁切），宽度铺满面板、高度随图变化；
- 写错或漏写 `type` → 面板不显示图片，正文照常显示（并在控制台告警）；
- 旧字段 `imageKey` 仍被兼容（等价于 `type`），但**新内容一律写 `type`**；
- 要加第四种类型，改的是**游戏本体**：新图放 `assets/images/news/`、在 `textureConfig.js` 登记、
  在 `latestNewsConfig.typeImages` 里加一行 → 需要发版。

## 六、客户端行为（写内容时需知的副作用）

1. **拉取时机**：启动加载画面期间与纹理/音频/字体并行；三源竞速，总窗口 3 秒，**不阻塞**进入游戏；
2. **弹窗时机**：进主菜单后弹出；若那时拉取还没结束，客户端最多再等 1.5 秒；
3. **面板动效**：自屏幕上方滑入居中，关闭沿原轨迹滑回；
4. **频率**：每次启动都弹，除非玩家勾选「今日内不再显示」（按本地日期判断，次日恢复）；
   没有「一条消息最多弹几次」的上限——同一条内容挂太久会每天弹，请及时更换或下线；
5. **降级链**：三源竞速 → 本地缓存（上次成功内容）→ 都没有则**退回自动打开游戏公告**；
6. **回看入口**：公告面板左侧导航顶部的「最新消息」（仅在本次启动有内容时出现）；
7. **安全边界**：内容按外部输入处理——正文纯文本渲染（不执行 HTML）、配图只认内置枚举；
8. **缓存**：Pages / jsDelivr 各有自己的 CDN 缓存，推送后可能需要等几分钟才生效（重启游戏可再试）。

## 七、发布与下线流程

1. 写 `text`（≤200 字）、选 `type`（通知类型）、更新 `id` 与 `updated`；
2. 确保 `enabled` 为 `true`；
3. 提交并推送到内容仓库的约定分支（默认 `main`）；
4. 等 CDN/Pages 缓存过期（数分钟）后，重启游戏即可看到；
5. **下线**：把 `enabled` 改成 `false` 并推送 → 客户端清缓存、不弹窗、退回自动开公告。

## 八、自检清单（发布前逐项确认）

- [ ] `news.json` 能被解析（JSON 合法）
- [ ] 文件是 UTF-8 无 BOM
- [ ] `schemaVersion` 为 `1`、`id` 唯一且格式正确、`updated` 已更新
- [ ] `text` ≤200 字、无 HTML/Markdown、换行用 `\n`
- [ ] `type` 是 `release` / `progress` / `issue` 之一（或不填）
- [ ] 没有残留已废弃的 `image` 字段（远端图片 URL）
- [ ] 没有残留已废弃的 `image` 字段
- [ ] `enabled` 为 `true`
- [ ] 一条消息长期挂着记得更换或下线
